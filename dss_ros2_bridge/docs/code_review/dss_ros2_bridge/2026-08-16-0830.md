## 잔존 findings 상태 갱신 (사용자 확인 2026-08-16 08:44)

앞선 delta 들이 `[잔존]` 으로 둔 항목 중 둘의 성격이 확인되었다. 코드 변경은 없고 **판정만 바뀐다**.

**함수 #1 — [topology][해결·정정] 스테레오 4개 노드의 원천 subject 부재 (결함 아님)**
   [2026-08-16 delta](2026-08-16.md) 가 High 로, [08:15 delta](2026-08-16-0815.md) 가 Medium `[잔존]` 으로 올렸던 항목이다. 사용자 확인 결과 **DSS 측 스테레오 카메라가 아직 개발 중**이라 subject 가 없는 것이 정상 상태다. 브리지 쪽 결함이 아니므로 findings 에서 내린다.
   남는 사실(판정 아님): 원천이 붙기 전까지 `DSSToROSStereoCamera*Node` 4개는 연결만 하고 발행하지 않는다. 기동 자체는 정상이며 heartbeat 도 나간다.

**함수 #9·#36 — [논리][이관] 쿼터니언 원천 이상 (SLAM 작업으로)**
   브리지 측 완화(노름 검사 + 정규화 + 경고)는 08:15 delta 에서 `[해결]` 이다. 남아 있던 **원천 확인**(DSS 가 보내는 노름 0.707 의 원인, 성분 누락 의심)은 사용자 결정에 따라 **SLAM 작업에서 다룬다** — 자세 품질이 실제로 문제되는 지점이 그쪽이고, 거기서 원천 값과 최종 자세를 함께 볼 수 있다.
   이관 시점의 사실: 브리지는 정규화된 단위 쿼터니언을 발행하며(실측 노름 1.000000), 원천이 비정규화일 때마다 5초 throttle 경고를 남긴다. 정규화된 값도 **원천이 틀리면 여전히 틀린 자세**라는 점은 유효하다.

이 갱신 이후 본 패키지의 미해결 항목: `dss.odom`·`dss.egoVehicle.snapShot` 미브리지(Medium) · GPS 경도 부호 의심(Low) · `getDefaultGateway` 하드코딩(Low) · 단위 테스트 0건(Medium) · heartbeat subject 명명 불일치(Info) · `launch.py` respawn 정책 부재(Info).
