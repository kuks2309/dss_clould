## B. 실기 구동으로 드러난 신규 findings

severity 분포: Critical 0 / High 2 / Medium 4 / Low 1 / Info 2
Verdict: REQUEST CHANGES

> 본 delta 는 작성 lane 이므로 `APPROVE` 불가(SOP rule 11). 아래 High 2건은 미조치 상태다.

### High

**함수 #9 `createImu` — [논리][신규] 정규화되지 않은 쿼터니언을 그대로 발행 (High)**
   실측: DSS 가 보내는 `dss::DSSIMU.orientation` 4필드가 모두 존재하는데 노름이 **0.707131** 이다
   (x=-0.0014346, y=-0.0081423, z=-0.0000354, w=0.7070826). 함수 #9(src/DSSToROSIMU.cpp:57-71)는 값을 그대로 복사하므로 `/dss/sensor/imu` 에 **비단위 쿼터니언이 그대로 나간다**. ROS/TF2·robot_localization 은 단위 쿼터니언을 전제하므로 자세가 틀리거나 경고·거부가 발생한다. 노름이 정확히 1/√2 에 가까운 것으로 보아 원천에서 성분 하나가 누락·오배치되었을 가능성이 크다.
   권고: 브리지에서 노름을 검사해 (a) 정규화 후 발행하거나 (b) 임계 이탈 시 로그 후 폐기. 동시에 DSS 측 원천 값을 확인해야 한다 — 브리지에서 정규화만 하면 잘못된 자세가 "정상처럼" 보일 수 있다.

**함수 #1 — [topology][신규] 스테레오 4개 노드의 원천 subject 가 존재하지 않는다 (High)**
   실측: NATS 서버 10초 관측에서 관측된 subject 는 `dss.sensor.imu`(119.8 Hz) · `dss.simTime.clock`(119.8) · `dss.sensor.gps`(12.0) · `dss.sensor.camera.rgb`(6.0) · `dss.sensor.lidar`(6.0) · `dss.odom`(10.9) · `dss.egoVehicle.snapShot`(10.9) · `dss.dashboard`(10.9) 뿐이다.
   `dss.sensor.camera.stereo.color` / `.depth` / `.infra1` / `.infra2` 는 **하나도 발행되지 않는다.** 즉 `launch.py` 가 띄우는 9개 중 **4개는 연결 후 영구히 아무것도 하지 않는다**(구동 확인: StereoColor 노드가 정상 기동·구독 등록 후 토픽 발행 0건). 노드는 살아 있고 heartbeat 도 나가므로 감시 측에서 정상으로 보인다.
   권고: 현 시뮬레이터 구성에서 스테레오가 없다면 `launch.py` 에서 제외하거나, subject 미수신이 N초 지속되면 경고를 낸다. 함수 #1 의 좀비 노드 문제(2026-08-15 High #5)와 같은 뿌리다 — "연결됐지만 데이터가 없다" 를 알릴 방법이 없다.

### Medium

**[topology][신규] DSS 가 발행하는 스트림 3종이 브리지되지 않는다 (Medium)**
   `dss.odom`(10.9 Hz, `DSSOdom`, `child_frame_id="base_link"`) · `dss.egoVehicle.snapShot`(10.9 Hz, `DssEgoVehicleSnapshot`) · `dss.dashboard`(10.9 Hz). 앞의 둘은 `proto/dss.proto:128,181` 에 정의까지 되어 있으나 대응 노드가 없다. `/odom` 없이는 표준 내비게이션 스택을 붙일 수 없다.
   권고: `DSSToROSOdomNode` 추가 검토. 범위 밖이면 debt 등록.

**함수 #13 `CreateGPSTopic` — [논리][신규] 경도 부호가 의심스럽다 (Medium)**
   실측 발행값: `latitude 37.6867`, `longitude 122.4375`, `altitude -49.02`. 위도 37.69 에 경도 **+122.44** 는 태평양 한가운데다. 샌프란시스코 좌표(37.69, **-122.44**)의 부호가 뒤집힌 형태로 보인다. 함수 #13 은 원천 값을 그대로 옮기므로 원인은 DSS 쪽일 수 있으나, `NavSatFix` 소비자에게는 그대로 잘못된 위치가 전달된다.
   권고: DSS 원천 값 확인. 브리지에서 임의 보정은 금지(원인 은폐).

**함수 #12 `createPointCloud2` — [논리][정정] 경계 검증 부재는 유효하나 현재 트리거되지 않는다 (2026-08-15 Critical → Medium 재평가)**
   실측: 현재 DSS 는 `width=6746 · point_step=14 · row_step=94444 · data=94444 B` 로 **정합**하고, 코드가 읽는 포인트당 14바이트가 `point_step` 과 정확히 같다. 따라서 **지금은 OOB 가 발생하지 않는다.**
   결함 자체(수신 필드를 검증 없이 포인터 산술에 사용)는 `[잔존]` 이다 — 같은 NATS 서버에 붙을 수 있는 임의 발행자가 `width`/`point_step` 을 조작하면 여전히 힙 오버리드·대량 할당이 가능하다. 다만 "현재 배포 구성에서 즉시 터진다" 는 아니므로 Critical → Medium 으로 내린다. 원 리뷰의 severity 를 실측 근거로 정정한다.
   권고: 변함없이 진입부 가드(`data().size() >= width * point_step`, `point_step >= 14`, `width` 상한).

**빌드 — [논리][해결] 워크스페이스 레이아웃이 ROS2 관례를 벗어나 재빌드가 실패했다 (Medium)**
   실측: `src/` 안에 `build/`·`install/`·`log/` 가 들어 있어 워크스페이스 루트가 `src/` 였고, 패키지 재배치 후 남은 CMake 캐시가 옛 경로를 가리켜 `colcon build` 가 실패했다(`The source ... does not match the source .../dss_ros2_bridge/dss_ros2_bridge/CMakeLists.txt used to generate cache`).
   조치: `src/{build,install,log}` 제거 후 저장소 루트에서 빌드 → 성공(10.7 s). 루트 `.gitignore` 에 `build/`·`install/`·`log/` 추가.

### Low

**함수 #9 — [논리][철회] "DSS 가 covariance 를 보내는데 코드가 버린다" (2026-08-15 Low → 철회)**
   실측: `orientation_covariance`·`angular_velocity_covariance`·`linear_acceleration_covariance` 배열이 실제로 오지만 **9개 원소가 전부 0.0** 이다. 유효 정보가 없으므로 이를 복사하면 "분산 0 = 완전 정확" 이라는 잘못된 의미가 되고, 현재 코드의 `[0] = -1`(unknown) 이 **더 정확하다.** 원 지적을 철회한다.
   (같은 이유로 함수 #13 GPS 의 `position_covariance` 전 0 지적은 `[잔존]` — 그쪽은 `-1`/UNKNOWN 표기조차 없다.)

### Info

**[정정] 2026-08-15 Medium `[QoS]` 의 성능 서술은 측정으로 반증되었다 (Info)**
   원 서술: "RELIABLE·depth 10 은 대용량 이미지에서 지연·버퍼 적체". 실측 결과 변경 전 유실률은 camera 0 % · lidar 0 % · imu 0.2 % 였다. 오히려 best-effort 전환 시 이미지에서 37.8 % 가 유실됐다. 근거 없는 성능 추정을 리뷰에 실었던 것을 정정한다.

**함수 #14 `createClock` — [논리][정정] 5 ms 하드코딩은 현재 시뮬레이터와 일치한다 (2026-08-15 Medium → Info 재평가)**
   실측: `custom_delta_time = 0.005` 로 코드의 `DT_NS` 와 같다. 다만 `frame_count × 5 ms` 가 `total_elapsed_time` 보다 **항상 0.5 ms 앞선다**(예: 계산 22552.540 s vs 원천 22552.53950 s). 시뮬레이터 델타가 바뀌면 전 시스템 시간축이 어긋나는 취약성은 `[잔존]` 이므로 원 권고(수신 `total_elapsed_time` 사용)는 유지하되, "지금 틀리다" 는 아니므로 Medium → Info 로 내린다.
