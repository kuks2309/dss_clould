- 대상 패키지: `src/dss_ros2_bridge`
- 검증: 실기(NATS `100.80.80.15:4222` + DSS 시뮬레이터 가동) before/after 계수 측정 + RViz2 렌더 확인

## 무엇을 바꿨나

pub/sub 의 QoS 를 정수 depth 인자(`, 10`)에서 rclcpp QoS 클래스로 교체했다. 정수 리터럴은 `rmw_qos_profile_default`(RELIABLE·depth 10) 로 해석되는데, 그것이 **의도한 선택인지 기본값 방치인지** 코드에서 구별되지 않았다.

함수 시그니처·전역 변수는 바뀌지 않았다(생성자 내부의 QoS 인자만 변경).

## 왜 이렇게 나눴나 — 측정이 방향을 두 번 바꿨다

1. **가설**: 922 KB 이미지를 RELIABLE 로 보내면 유실이 클 것이다 → 전 센서 토픽을 `SensorDataQoS` 로.
2. **측정 1(변경 전)**: 유실이 사실상 0 이었다. 성능 근거 소멸. (초기에 `ros2 topic hz` 가 5.2 Hz 를 보고했으나 짧은 관측창 아티팩트였다.)
3. **측정 2(전면 SensorDataQoS 적용 후)**: 이미지에서 **37.8 % 유실** 발생. 922 KB 는 RTPS 조각화 전송이라 best-effort 에서 조각 1개 손실이 샘플 전체 손실이 된다. 148 KB 인 lidar 는 0 %.
4. **결론**: 관례(전부 best-effort)가 아니라 **메시지 크기**로 나눈다. 이미지만 reliable.

## before / after (동일 조건 계수 측정, 20 초 창)

| 토픽 | 크기 | before (전부 RELIABLE) | 전면 SensorDataQoS 시도 | after (최종) |
| --- | --- | --- | --- | --- |
| `/dss/sensor/camera/rgb` | 921,600 B | 0 % | **37.8 % 유실** | **0.0 %** (RELIABLE 유지) |
| `/dss/sensor/lidar3d` | 148,478 B | 0.0 % | 0.0 % | 0 % (SensorDataQoS) |
| `/dss/sensor/imu` | 수백 B | 0.2 % | 0 % | 0 % (SensorDataQoS) |
| `/clock` | 수십 B | 0.2 % | — | 15.7 %\* (ClockQoS) |

\* `/clock` 의 15.7 % 는 **구독자 depth 1** 특성이다. clock 은 절대 시각이라 최신 1 개만 유효하고 rclcpp `TimeSource` 자체가 depth 1 로 구독한다. 유효 수신 122.3 Hz 로 기능상 문제 없음 — 성능 지표로 오독하지 말 것.

## 호환성 영향 (실증됨)

best-effort 발행자는 reliable 구독자와 **연결되지 않는다**(RxO: offered < requested). 변경 후 reliable 구독자로 측정하니 4개 토픽 모두 수신 0 건이었고 rclcpp 가 경고를 냈다:

```text
New publisher discovered on topic '/clock', offering incompatible QoS.
No messages will be received from it. Last incompatible policy: RELIABILITY
```

- 영향 받는 토픽: `/dss/sensor/imu`, `/dss/sensor/gps/fix`, `/dss/sensor/lidar3d`, `/clock`
- 외부 소비자 조치: `rclcpp::SensorDataQoS()` / rclpy `qos_profile_sensor_data` 로 맞출 것. RViz2 는 디스플레이의 Reliability 를 `Best Effort` 로.
- 이미지 5종은 reliable 유지이므로 기존 소비자 영향 없음.

## 남은 것

- **권장 후속**: 이미지를 `sensor_msgs/CompressedImage`(DSS 원본 JPEG 83 KB 그대로)로 발행하면 조각화가 사라져 이미지도 `SensorDataQoS` 로 수렴할 수 있고 대역이 11 배 준다. 소비자가 받는 형식이 바뀌는 기능 변경이라 이번 범위 밖.
- QoS 파라미터화(`qos_overrides`) 미적용 — 현재는 코드 상수.
