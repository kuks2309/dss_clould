# dss_motion_control 수정 이력 (패키지 병기본)

## 2026-08-17 — 패키지 신설 (v0.1.0, dss_motion_interfaces 동반)

원본 amr_motion_control_2wd 전문 리뷰(docs/code_review/amr_motion_control_2wd/2026-08-17.md)
기반 Ackermann 차량용 재구현:

- 구조 계승: 액션 서버 + nav_msgs/Path + 사다리꼴 프로파일 + 측위 워치독 + 가드
  (취소·타임아웃·횡이탈·측위상실) + 상호 배제. 공통 PathTrackingServer 기반클래스로
  원본의 85% 파일 중복 해소(원본 Info 권고).
- 재정식화(원본 Medium 2건 정정): Stanley 전륜축 기준 CTE / Pure Pursuit
  κ=2 sinα/Ld 정식 → δ=atan(축거·κ). 제자리 최종 정렬 제거(차량 불가).
- 출력: /dss/control(DssControl) 20 Hz — DSSControlNode UDP 릴레이 재사용
  (jog ADR 의 "자율주행 스택 재사용" 설계 이행). 종방향 = 속도 추정(TF 미분+이동평균)
  + PI throttle / 비례 brake, 정지 시퀀스(브레이크 유지→0 명령 릴리스).
- 목표점 UX: /goal_pose(RViz 2D Goal Pose)→직선 경로→기본 제어기 자동 발행 +
  send_goal CLI.
- 캘리브레이션 대상 파라미터(ADR D8): wheelbase(2.7)·max_steer_deg(30)·steer_sign(+1)
  — 라이브 저속 실측으로 확정 예정.

검증: 기하·프로파일·워치독 단위시험 10/10 (CTE 부호·lookahead 보간·조향 방향·
사다리꼴/삼각·점프 검출), 노드 스모크(액션 2종 등록·무측위 정상 거부).
라이브 주행 검증은 미실시 — 다음 단계.

## 2026-08-17 (2차) — 라이브 캘리브레이션 반영 (ADR D8 이행)

dss_motion_control_node.py 기본값 확정 (저속 실주행 2회 실측):
- `steer_sign` +1→-1 — steer +0.4 → 우회전(Δyaw -2.4°), steer -0.3 → 좌회전(+4.9°) 대칭 확인.
  δ>0(좌) 명령을 DSS 좌회전으로 보내려면 부호 반전 필요.
- `max_steer_deg` 30→10 — 정상 곡률 κ→δ 역산 2회 일치(steer 0.4 에서 유효 δ≈4.05°,
  0.3 에서 ≈2.75° → 스케일 9~10°/1.0).
- throttle 데드밴드 실측: 0.12 무동작, 0.25+ 기동 (throttle_max 0.35 유지 타당).

1차 라이브(PP, 52.6 m 목표): 27 m 추종 성공(CTE ≤0.20→0.07 m 수렴, 3.3 m/s) 후
타 세션 mapviz initialize_origin 의 벽시계 /tf 오염으로 측위 동결 → 워치독 정상 발동(-3).
제어기 자체 결함 아님 — 오염원 제거 후 재시험.

## 2026-08-17 (3차) — 라이브 주행 검증 + 실측 수정 4건

**시험 결과** (RTAB 측위 + /dss/control 릴레이):
| 시험 | 결과 |
| --- | --- |
| PP 직선 60 m | 도달 (26.4 m 구간, 최종 CTE -0.07 m) |
| Stanley 직선 40 m | 도달 (39.3 m, CTE +0.04 m) |
| PP 좌사선 (+5 m 횡) | 도달 (39.9 m, CTE +0.06, 과도 최대 0.23) |
| Stanley 사선 (+3 m 횡) | 도달 (33.9 m, CTE -0.01) — 충돌 후 틀어진 초기 방향 자가 복구 |
| 우사선 2회 (y<-1 대역) | 도로변 장애물 충돌 — 정체 가드가 4 s 에 자동 정지(안전장치 실증) |

**실측 수정**:
1. `target_gear` 0→**1**: 실측 +1=전진(D)·0=유지·-1=후진 — 0(유지)은 직전 후진 기어를
   물려받아 무동작. (comment 의 "0=유지(전진)" 은 유지≠전진이었음)
2. `throttle_deadband` 피드포워드 0.15 신설: 실측 스로틀 ~0.2 미만 무동작 —
   PI 만으로는 저속 명령에서 데드밴드를 못 넘어 출발 지연/정체.
3. **정체(stall) 가드 신설**: 명령>0.5 m/s·실속도<0.15 가 4 s 지속 → 충돌 판정
   status -4 정지 (충돌 실측 반영 — 이전엔 장애물을 계속 밀었음).
4. send_goal **SIGINT/SIGTERM 시 goal 취소 전송**: 클라이언트 타임아웃 사살 후
   서버 좀비 액션이 계속 주행하던 결함 차단.

**환경 이슈(제어기 외)**: 릴레이(DSSControlNode)는 DSS 리셋 후 stale — 재기동 필요.
DSSToROSClockNode 는 자기 use_sim_time=true 파라미터 없이는 /clock 을 조용히 버림
(DSSToROSClock.cpp:24) — 기동 시 `-p use_sim_time:=true` 필수. 타 세션 mapviz
initialize_origin 의 벽시계 /tf 는 sim TF 트리를 오염시킴(동시 기동 금지).

## 2026-08-17 (4차) — waypoint 속도·UTM 표시 확장 (사용자 지시 3건)

**지시**: ① "waypoint 목표 속도도 포함" ② "GPS값도 utm으로... gps yaw 도" →
"x,y,yaw, speed, utm_x, utm_y, utm_yaw 이렇게 나와야죠" ③ "여기에(waypoint 테이블)
utm 좌표도 넣어달라구요"

**인터페이스**: 양쪽 .action Goal 에 `float64[] point_speeds` 추가 —
path.poses 와 같은 길이, 각 지점 도달 목표 속도(0 이하 = 제한 없음). 미지정 시
기존 동작 그대로(send_goal·goal_pose 브리지는 비워 보냄 — 하위 호환).

**서버**: `geometry.speed_limit_at`(G9) — 미래 느린 지점을 √(v_i²+2a·gap) 제동
거리로 선반영 + 현 구간 속도 상한. `_run` 루프에서 프로파일 속도에 min 적용.
상한이 min_speed(0.8) 아래로 내려가면 min_speed 가 우선(정지마찰 극복 우선).

**UI (waypoint_ui)**:
- 테이블 5열: X·Y·**UTM E·UTM N**·속도. 클릭 시 속도 스핀 값이 그 waypoint 목표
  속도로 기록(셀 편집 가능, U4a 파싱 하한 0.3). on_start 는 레그별 densify 로
  보간점에 레그 속도를 물려주고 `point_speeds` 정렬 배열 전송, 마지막 지점 0.
- 차량 상태 그룹: `x | y | yaw | speed` (TF+quaternion→yaw, SpeedEstimator 재사용)
  + `utm_x | utm_y | utm_yaw` (GPS front pyproj UTM 변환, yaw=atan2(front-rear)).
  GPS 브리지 2 인스턴스(`gps_front/fix`·`gps_rear/fix`, NATS dss.sensor.gps.*) 필요.
- waypoint 의 UTM 좌표: map→UTM 은 단순 오프셋이 아님(DSS GPS 합성 좌표 — 축척
  ≈104·재시작마다 원점 변동) → 주행 중 (map, UTM) 대응점을 1 m 간격 수집,
  기선 ≥2 m 확보 시 `similarity_2pt`(G10, 축척+회전+평행이동) 로 변환 추정해
  UTM 셀 채움/갱신. **기선 확보 전(정지 상태)은 '—' 표시가 정상.**

**검증**: pytest 12/12 (speed_limit_at·similarity_2pt 신규 2건 포함), UI 캡처로
5열 테이블·차량 상태 7값 표시 확인(x 229.72 / utm_x 325595.69 / utm_yaw -75.2°).
point_speeds 실주행(감속 도달) 검증은 다음 주행 시험에서.

## 2026-08-17 (5차) — waypoint 테이블 yaw 컬럼 + 등록 무동작 진단

**지시**: "waypoint 등록도 없네요", "테이블에 yaw 값들이 빠져있네"

**진단(등록 무동작)**: 코드 결함 아님 — /clicked_point 발행자(rviz2)↔구독자
(waypoint_ui) 연결·QoS 정합 확인 후 테스트 포인트 발행으로 행 등록 실증(sim,
2026-08-17 21:24). 사용자 클릭 시점이 UI 재기동(20:52~20:57 3회)과 겹쳐 유실된
것. 참고: RViz Publish Point 도구는 1회성 — 클릭마다 도구 재선택 필요.

**yaw 컬럼**: 테이블 7열(X·Y·**Yaw**·UTM E·UTM N·**UTM Yaw**·속도).
waypoint yaw = 이전 점(첫 점은 차량 현재 위치)→해당 점 atan2 진행 방향,
UTM Yaw = yaw + 유사변환 회전각(기선 미확보 시 '—'). 파생 3컬럼은
`_refresh_derived_cells` 로 추가/삭제/변환 개선 시 일괄 재계산.

**검증**: 테스트 포인트 2발 발행 → 행 2개·yaw +46.6°/+26.6°(수계산 일치) 캡처
확인(sim, 2026-08-17 21:26).

## 2026-08-17 (7차) — UI 경유 시험 주행 완주 + TF 동결 오발 진단

**시험**: waypoint UI 로 (250,2)·(268,2) 등록 → [추종 시작] 클릭 → PP 추종.
1차 시도는 4 s 정체 가드 발동("충돌 의심") — **오발**이었다.

**진단**: 제어 노드 로그 시작 pose=(229.72,-0.59) vs 실위치 (234.2,-1.1) —
이전 벽시계 TF 오염이 제어 노드 버퍼에 잔존, 신규 sim TF 전량 거부
(TF_OLD_DATA 홍수)로 **포즈 동결** → v_est=0 → 정체 가드 오발. 라이다 프로브
전방 8 m 무장애물·전진 펄스 0.45 m/2 s 로 물리 충돌 배제. 현재 /tf 스트림은
청정(sim 스탬프만) — 오염원 소멸 후에도 tf2 버퍼는 자연 회복 불가, **노드
재기동이 유일 복구**(클럭 오염 사고와 동일 계열, 재발 3번째).

**결과(재기동 후)**: 시작 pose 실위치 일치 → 28.5 m 주행, 22.4 s, 최종 CTE
0.13 m, "도달 성공"(sim, 2026-08-17 21:37). 주행 중 기선 확보로 테이블 UTM
E/N/Yaw 자동 충전 확인.

**알려진 표시 특성(추후)**: 1번 waypoint 의 Yaw 는 '차량 현재 위치 기준'이라
주행하며 계속 갱신됨(통과 후 -179° 등) — 등록 시점 고정이 자연스러움.
정체 가드가 TF 동결과 실충돌을 구분 못하는 한계도 확인(포즈 불변+명령>0 은
두 경우 동일) — 워치독에 '포즈 동결 감지' 추가가 후보.
